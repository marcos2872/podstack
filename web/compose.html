Compose

Veja projetos Compose agrupados por labels, suba e derrube stacks, acompanhe logs por serviço e abra o YAML ou o diretório do projeto.

PodStack 0.1.3Documentação de usuário

Visão geral

O PodStack detecta projetos Compose pelas labels com.docker.compose.project e com.docker.compose.service nos containers. Os containers são agrupados pelo nome do projeto, e não pela pasta. O status do projeto é agregado a partir dos serviços.

O engine continua sendo o Podman. O provider Compose é um binário externo que fala com o socket do Podman: docker-compose, podman compose ou docker compose. A ordem de detecção é docker-compose, podman compose e docker compose; PODSTACK_COMPOSE_PROVIDER força um binário.

Subir um projeto

  1. Abra Compose na barra lateral.
  2. Clique em Up por diretório e informe o Diretório do projeto.
  3. Confirme em Subir. O Compose procura compose.yaml ou docker-compose.yml no diretório.
  4. Acompanhe o progresso; ao terminar, o projeto aparece na lista com status e serviços.

Operar o projeto

Na lista, selecione um projeto para usar Up, Down, Restart e Logs. Os botões Abrir YAML e Abrir diretório abrem o arquivo e a pasta do projeto. A GUI não tem botões separados de start e stop por projeto; para iniciar sem recriar ou parar sem derrubar, use a CLI (podstack compose start|stop).

Down remove os containers e a rede do projeto. Por padrão, os volumes são preservados; marque Remover volumes também no diálogo para apagá-los. O diálogo deixa claro quando os volumes serão preservados.

Serviços e logs

Clique em Logs com um projeto selecionado. O diálogo permite escolher um serviço ou todos e usar Assinar para iniciar o stream. Os logs por serviço não misturam saídas; o modo agregado combina todos os serviços. Ctrl+C encerra a assinatura no CLI; na GUI, feche o diálogo ou pare a assinatura.

Na CLI

Comando Flags O que faz
podstack compose ls / list — Lista projetos agrupados por labels.
podstack compose up <diretório> [serviço] — Sobe o projeto; sempre destacado (não há -d).
podstack compose down <diretório> [serviço] --volumes Derruba o projeto; sem --volumes, preserva os volumes.
podstack compose restart <diretório> [serviço] — Reinicia o projeto ou um serviço.
podstack compose stop <diretório> [serviço] — Para o projeto ou um serviço.
podstack compose start <diretório> [serviço] — Inicia o projeto ou um serviço.
podstack compose logs <projeto> [serviço] — Stream agregado ou por serviço; Ctrl+C encerra. 
podstack compose up ~/projetos/app
podstack compose ls
podstack compose logs app web
podstack compose down --volumes ~/projetos/app

# forçar o provider
PODSTACK_COMPOSE_PROVIDER=docker-compose podstack compose up ~/projetos/app

O up do CLI recebe o diretório, não um -f, e sempre roda destacado. Para diagnosticar um provider ausente, veja PODSTACK_COMPOSE_PROVIDER_MISSING em Compose e builds.

Limitações

  • O compose up do CLI não aceita -f, -d nem outras flags do provider; ele recebe o diretório e roda destacado.
  • O projeto é identificado pela label do Compose; containers criados sem essas labels não são agrupados.
  • Domínios customizados via Compose e a montagem da CA local em containers de Compose estão pendentes (T6-08).
  • O provider precisa estar instalado e apontar para o socket do Podman; o PodStack não instala o provider automaticamente.
  • O status agregado é derivado dos containers; um serviço que falhou pode aparecer como parcial, não como um estado próprio do Compose.
