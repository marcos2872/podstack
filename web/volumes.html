Volumes

Persista dados fora do ciclo de vida dos containers, clone volumes para testes e mova conteúdo com export/import .tar.zst ou importação de um diretório do host.

PodStack 0.1.2Documentação de usuário

Visão geral

A seção Volumes mostra os volumes nomeados do Podman com NAME, DRIVER, SIZE e LINKS (quantos containers usam o volume). O CLI também mostra o MOUNTPOINT no storage do Podman.

Volumes nomeados sobrevivem à remoção do container. A remoção do volume é uma operação separada e destrutiva; volumes em uso por containers são bloqueados.

Na interface

Criar, clonar e importar do host

  1. Abra Volumes na barra lateral.
  2. Clique em Criar, informe Nome e, se necessário, o Driver; confirme em Criar.
  3. Para copiar um volume, selecione a origem e clique em Clone. Informe o Destino (novo volume) e confirme.
  4. Para popular um volume com um diretório do host, selecione o volume e clique em Importar do host. Informe o Diretório de origem e confirme em Importar.

A importação do host é aditiva: o conteúdo é copiado para o volume, sem apagar o que já existe. O clone usa reflink quando o filesystem suporta e faz fallback para cópia quando não suporta.

Prune e remoção

Prune abre uma prévia com os volumes sem containers usando, o tamanho de cada um e o total recuperável estimado. Confirmar o prune apaga esses volumes e seus dados.

Remover apaga o volume selecionado após confirmação. Volumes em uso bloqueiam a remoção; a multi-seleção permite remover vários volumes de uma vez. A CLI oferece --force, que deve ser usado apenas quando você tem certeza de que o volume não é mais necessário.

Dados de volumes são perdidos

Prune e remoção apagam os dados do volume. Faça um export antes de limpar volumes que contenham bancos, caches ou arquivos de trabalho. A remoção de um container não remove o volume nomeado.

Na CLI

Comando Flags O que faz
podstack volumes ls / list — Lista nome, driver, tamanho, links e mountpoint.
podstack volumes create <nome> --driver driver Cria um volume nomeado.
podstack volumes rm <nome> --force Remove o volume.
podstack volumes prune — Remove volumes sem containers usando.
podstack volumes clone <origem> <destino> — Clona o conteúdo para um volume novo (reflink/fallback).
podstack volumes export <nome> <arquivo> --force Exporta para .tar.zst.
podstack volumes import <nome> <arquivo> --force Importa um .tar.zst; sem --force, não sobrescreve um volume existente.
podstack volumes import-host <nome> <diretório> — Copia um diretório do host para um volume novo. 
podstack volumes create dados
podstack volumes create dados --driver local
podstack volumes clone dados dados-teste
podstack volumes export dados ~/dados.tar.zst
podstack volumes import dados-restaurado ~/dados.tar.zst
podstack volumes import-host importado ~/projetos/app/dados
podstack volumes ls
podstack volumes rm dados-teste
podstack volumes prune

Em export/import, o primeiro argumento é o nome do volume e o segundo é o arquivo. O formato é .tar.zst.

Limitações

  • A GUI importa diretórios do host, mas não exporta nem importa .tar.zst; use a CLI para esses fluxos.
  • O mountpoint aparece apenas na tabela do CLI, não na lista da GUI.
  • O tamanho exibido vem do uso de disco do engine e pode demorar a refletir alterações recentes.
  • Volumes em uso não são removidos sem --force; a GUI não oferece esse controle.
  • O clone é uma cópia; alterações posteriores em um volume não são propagadas para o outro.
