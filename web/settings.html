Configurações

Todas as preferências vivem no daemon, com um schema validado de 86 chaves. A GUI e a CLI leem e escrevem os mesmos valores; nada é gravado direto no arquivo pela interface.

PodStack 0.1.4Documentação de usuário

Visão geral

Abra Configurações pelo item Settings na barra lateral ou com Ctrl+,. O diálogo é dirigido pelo schema do daemon (settings.schema) e mostra uma categoria por vez, com a chave, a descrição, o valor padrão, um badge de reinício quando necessário e o controle adequado ao tipo.

Cada linha tem Salvar e Restaurar. O valor é validado pelo daemon (tipo, faixa, enum) e um valor inválido não é salvo. Chaves que exigem reinício acumulam um aviso “Reinicie o PodStack para aplicar: …” até o app ser reiniciado.

O arquivo é ~/.config/podstack/config.json (0600), com escrita atômica e schemaVersion: 1. A precedência é: flag de CLI da invocação, variável de ambiente PODSTACK_*, config.json e defaults compilados.

Chaves marcadas como hidden continuam no schema e na CLI, mas não aparecem no diálogo e, nesta versão, ainda não têm efeito no app. Elas são úteis para inspeção e planejamento, não para mudar o comportamento em runtime.

Como todas as chaves docker.* estão marcadas como hidden, a categoria Docker aparece sem linhas no diálogo. Elas não têm efeito no app 0.1.4; use podstack config get docker.<chave> ou o schema apenas para inspeção.

Geral

Atualizações

Não existe aba Updates. O bloco Atualizações do PodStack fica no topo da categoria Geral e contém:

  • O checkbox Verificar atualizações ao iniciar, que grava updates.mode como check ou off.
  • O botão Verificar atualizações, que consulta o manifesto assinado com force=true e mostra o resultado ao lado.

As chaves updates.channel, updates.feedUrl, updates.publicKey e updates.lastCheck são internas: não aparecem na GUI, mas continuam disponíveis no schema e na CLI (podstack config e podstack update --check). A checagem automática roda alguns segundos após abrir e a cada 6 horas, respeitando updates.mode=off.

Atualização assistida

A verificação só consulta o manifesto assinado. A partir da 0.1.4, a GUI oferece Instalar atualização e o CLI aceita podstack update --install, com consentimento, assinatura e reinício; em caso de falha, use --resume para retomar ou --clear-state para limpar. O caminho manual por sudo dnf upgrade podstack ou sudo apt upgrade podstack continua válido.

Tema, escala, bandeja e idioma

app.theme aceita system, dark e light; app.fontScale vai de 80 a 150 (%). O tema do site segue a preferência do sistema e tem um botão de alternância próprio, independente do app.

app.startAtLogin cria/remove o autostart com --hidden; app.keepRunningInTray faz fechar a janela esconder para a bandeja; app.showInTray controla o ícone; app.notifications cobre falha, OOM e unhealthy. app.language aceita pt-BR e en-US e exige reiniciar. app.showOnboarding controla a exibição do onboarding incompleto.

Bandeja depende do host

Se o host não oferecer StatusNotifier/SNI, app.keepRunningInTray é ignorado e fechar a janela encerra a GUI. O PodStack nunca fica sem janela e sem ícone de bandeja.

Rede e portas

network.proxy aceita none, auto ou uma URL http://, https://, socks5:///socks5h://. auto herda as variáveis de proxy já definidas no ambiente do daemon. As exclusões de network.proxyExclude aceitam host, domínio, *.domínio ou CIDR e só valem no modo URL. A configuração é lida na criação: containers, machines e stacks Compose existentes precisam ser recriados.

network.httpPort (18080) e network.httpsPort (18443) mudam as portas do proxy e exigem reiniciar. Configs gravadas por versões anteriores com 8080/8443 são migradas automaticamente para os novos defaults; valores customizados são preservados. network.exposeLan expõe portas/domínios na LAN e também exige reinício; o firewall é liberado separadamente. network.bridge desliga o proxy HTTP e o DNS quando false.

As chaves network.subnet4, network.ipv6 e network.domainsMode estão no schema/CLI, mas ocultas na GUI.

podstack config get network.httpPort
podstack config set network.httpPort 19080
podstack config set network.https true
podstack config set network.proxy socks5://127.0.0.1:1080
podstack config add network.proxyExclude .internal
podstack config remove network.proxyExclude .internal
podstack config reset network.https --yes
systemctl --user restart podstack.service

Machines e retenção

Os defaults de Nova machine vêm de machines.cpus (2), machines.memoryBytes (4 GiB), machines.diskBytes (20 GiB), machines.forwardSshAgent e machines.isolated. O campo machines.default define a machine usada por podstack ssh sem argumento. As chaves machines.forwardPorts, machines.exposePortsToLan, machines.sshPortStart, machines.autoSuspend e todo o grupo ssh.* estão ocultos na GUI e disponíveis no schema/CLI.

A retenção de jobs e logs de build é representada por advanced.jobRetentionDays (7) e advanced.buildLogRetentionDays (30), também ocultas na GUI e sem efeito no app 0.1.4. O cache de imagens cloud usa advanced.cloudImageCacheBytes (20 GiB). Consulte os valores com podstack config get; não conte com eles para mudar a retenção nesta versão.

Chave Default O que controla
advanced.jobRetentionDays 7 dias Retenção de jobs.
advanced.buildLogRetentionDays 30 dias Retenção de logs de build.
advanced.cloudImageCacheBytes 20 GiB Cache de imagens cloud.
notifications.diskThresholdPercent 90% Aviso de disco baixo (histerese de 5 pontos, cooldown de 6 h).
advanced.logLevel info Nível de log; aplicado em runtime, sem reinício.
advanced.logRetentionDays 7 Retenção dos logs do app em dias (1–30).
advanced.logMaxBytes 10 MiB Tamanho máximo de cada arquivo de log (1 MiB–1 GiB).

Diagnóstico e report

diagnostics.includeLogs inclui logs no report e diagnostics.redact redige segredos. Ambos são visíveis na GUI. O report é gerado por podstack report --include-logs, fica em ~/.local/state/podstack/reports/ com permissão 0600 e o comando imprime o caminho e o SHA-256. Revise o conteúdo antes de compartilhar: ele é redigido, mas pode conter nomes de containers, caminhos e configuração.

As chaves advanced.logLevel, advanced.logRetentionDays e advanced.logMaxBytes são expostas na GUI e aplicadas em runtime (restartRequired: false); diagnostics.includeLogs passou a default false. As chaves advanced.helper.enabled, advanced.dns.install e advanced.ca.install continuam internas/CLI nesta versão; a GUI prioriza os fluxos assistidos do setup e do helper.

Na CLI

Reset e configuração pela CLI

Restaurar em uma linha devolve o valor padrão daquela chave. O reset total fica na CLI: podstack config reset --all --yes restaura as configurações e preserva todo o bloco setup.* (incluindo dockerPolicy). Machines e dados não são tocados. Em modo não interativo, config reset sem --yes retorna exit 2.

O schema tem 86 chaves e pode ser inspecionado com podstack config schema --json, que devolve tipo, default, enum, faixa e restartRequired. Chaves marcadas como hidden continuam no schema e na CLI, mas não aparecem no diálogo.

podstack config show
podstack config show --json
podstack config get network.httpPort
podstack config set app.theme dark
podstack config set app.fontScale 110
podstack config schema --json
podstack config reset network.https --yes
podstack config reset --all --yes

Necessidade Na GUI Na CLI
Ver o valor efetivo Categoria → linha podstack config get <chave>
Alterar uma chave Editar → Salvar podstack config set <chave> <valor>
Voltar ao padrão Restaurar na linha podstack config reset <chave> --yes
Reset total — (use a CLI) podstack config reset --all --yes
Listar o schema Categoria e controle por tipo podstack config schema --json
Ver atualizações Geral → Verificar atualizações podstack update --check
Aplicar reinício pendente Reabrir o PodStack systemctl --user restart podstack.service

Limitações

  • A categoria Docker aparece vazia na GUI porque todas as chaves docker.* estão ocultas; use a CLI/schema.
  • Não existe aba Updates; o controle está em Geral e as chaves updates.* são internas/CLI.
  • Chaves ocultas (retenção, log level, subnet, IPv6, SSH, telemetria etc.) aparecem no schema/CLI, mas não têm efeito no app 0.1.4.
  • Chaves com restartRequired só valem depois de reiniciar o PodStack.
  • O reset total não está na GUI; use a CLI e revise o que será preservado (setup.*).
