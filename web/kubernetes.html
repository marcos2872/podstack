Kubernetes

Habilite um cluster k3s local em uma VM dedicada, use um kubeconfig isolado e acompanhe Pods, Services, logs e port-forward sem sair do PodStack.

PodStack 0.1.1Documentação de usuário

Visão geral

O Kubernetes do PodStack roda em uma VM dedicada com k3s. O k3s não é instalado no host e o PodStack não usa kind no v1. O kubectl precisa estar instalado no host para você operar o cluster; o PodStack não instala o cliente.

O kubeconfig fica isolado em ~/.local/share/podstack/kubeconfigs/<cluster>.yaml (0600) e o contexto recebe o prefixo podstack-. O PodStack não altera ~/.kube/config. A API é exposta em 127.0.0.1:<porta>.

Na interface

  1. Abra Kubernetes na barra lateral.
  2. Clique em Habilitar (ou Habilitar Kubernetes) e acompanhe o job: criação da VM, instalação do k3s e espera do nó Ready.
  3. Quando o cluster estiver ativo, use as abas Pods e Services. A página atualiza a cada 2 segundos.
  4. Selecione um Pod e clique em Logs para escolher o container e acompanhar o stream.
  5. Use Excluir para remover um Pod ou Service, com confirmação, e Port-forward para encaminhar uma porta local até o Pod.
  6. Para encerrar, use Desabilitar ou Reset; ambos removem a VM, o disco e o kubeconfig.

O botão Port-forward abre um diálogo com Porta local e Porta no pod; o indicador mostra ativo: 127.0.0.1:<local> → <remota>. O encaminhamento é feito via API do cluster. Para Services, use kubectl port-forward diretamente nesta versão.

Desabilitar para a VM e remove o cluster; Reset é equivalente a desabilitar com force=true. Os dados dos workloads são perdidos nos dois casos.

Desabilitar/Reset são destrutivos

A VM, o disco e o kubeconfig são removidos. Não há um “parar e manter o cluster” separado: kube stop e kube disable fazem a mesma coisa nesta versão.

Na CLI

Comando Flags O que faz
podstack kube info --cluster NOME, --json Mostra estado, contexto, API e kubeconfig.
podstack kube env --cluster NOME Imprime export KUBECONFIG=....
podstack kube start — Cria a VM e instala o k3s.
podstack kube stop --force Remove a VM, o disco e o kubeconfig.
podstack kube disable --force Sinônimo de stop nesta versão.
podstack kube context — Mostra o current-context do kubeconfig.
podstack kube context use <nome> — Troca o contexto explicitamente. 
podstack kube start
podstack kube info
eval "$(podstack kube env)"
kubectl get nodes
kubectl get pods -A

podstack kube context
podstack kube context use podstack-default
podstack kube stop

O kube env imprime o export KUBECONFIG=...; use eval para aplicar na sessão atual. O arquivo não é copiado para ~/.kube/config.

TLS, SANs e exposição

Os recursos da VM do cluster são configuráveis em Configurações → Kubernetes: kubernetes.cpus, kubernetes.memoryBytes, kubernetes.diskBytes e kubernetes.tlsSan (SANs extras do API server). Alterações nesses campos exigem reiniciar o PodStack.

kubernetes.exposeServices=true faz o port-forward de Service usar 0.0.0.0 (LAN) em vez de loopback. O firewall do host ainda precisa ser liberado separadamente. Não há NodePort/LoadBalancer nativos em 0.1.1.

TLS SANs

Se você acessa a API por um nome ou IP diferente, adicione o SAN em kubernetes.tlsSan antes de habilitar/reiniciar o cluster. O kubeconfig aponta para 127.0.0.1; use podstack kube env para apontar o kubectl ao arquivo correto.

Limitações

  • Não há NodePort/LoadBalancer nativos nem k8s.podstack.local (T5-07 parcial).
  • A troca de contexto é explícita; não há troca automática por projeto (T5-08 parcial).
  • kube stop e kube disable removem a VM, o disco e o kubeconfig; não há “parar e manter”.
  • O port-forward da GUI é para Pods; para Services, use kubectl port-forward.
  • O kubectl não é instalado pelo PodStack.
  • O cluster depende de KVM para desempenho; sem /dev/kvm, a VM usa TCG e fica lenta.
