Instalação

Do pacote ao primeiro container: instale o PodStack no Fedora ou Ubuntu, inicie o daemon de usuário e conclua o setup em 7 etapas.

PodStack 0.1.4Fedora 43/44 · Ubuntu 24.04–26.04

Rootless por padrão

O daemon roda com o seu usuário e o socket de controle fica em $XDG_RUNTIME_DIR/podstack/control.sock, com diretório 0700 e socket 0600. Ações de sistema passam pelo podstack-helper com polkit e allowlist. O Docker não é removido por padrão.

Requisitos

Item Requisito Observação
Sistema Fedora 43/44 ou Ubuntu 24.04+ Wayland ou X11. O RPM é o caminho principal no Fedora; o DEB é construído no Ubuntu 24.04 e roda em 24.04–26.04.
Podman Fedora: 5.8+; Ubuntu: 4.9+ (5.8 recomendado) O PodStack usa o podman.socket do usuário; não reimplementa o runtime.
systemd Fedora: 257+; Ubuntu: 255+ Socket e serviço de usuário podstack.socket/podstack.service.
Polkit Agente de autenticação na sessão Necessário para o podstack-helper; em sessão gráfica o prompt aparece normalmente.
OpenSSH Cliente ssh e scp Usado pelas machines e pelo encaminhamento de chaves.
Qt Qt 6.4+ em runtime Fedora 43/44: 6.10/6.11; Ubuntu 24.04: 6.4.2. O DEB leva o qtermwidget 2.0.0 embutido.
KVM /dev/kvm legível e gravável Opcional. Sem KVM, as machines usam TCG (muito mais lentas).
QEMU/OVMF/virtiofsd Instalados para machines O setup pode instalar; o virtiofsd atende os mounts virtiofs.
Caddy Opcional Necessário para HTTPS em *.localhost/*.podstack.local.
docker-compose Opcional Provider usado pelos projetos Compose; a engine continua sendo o Podman.
k3s no host Não necessário O Kubernetes roda em uma VM dedicada criada pelo PodStack.

Confira o Podman antes de instalar:

podman --version
podman info

podman info deve funcionar sem sudo. Se o socket rootless não estiver ativo:

systemctl --user enable --now podman.socket

Instalar o pacote

Fedora (RPM)

sudo dnf install ./podstack-0.1.3-1.fc44.x86_64.rpm

# com um repositório configurado
sudo dnf install podstack

Ajuste fc44 e x86_64 para a release e a arquitetura do seu Fedora. O %post habilita podstack.socket globalmente; o daemon sobe sob demanda na primeira conexão.

Ubuntu (DEB)

sudo apt install ./podstack_0.1.3_amd64.deb

O postinst habilita podstack.socket por usuário e o podstack-helper.service. O qtermwidget 2.0.0 vai embutido no binário.

Build a partir do código

Para testar uma versão local, o caminho é cmake --preset dev, cmake --build --preset dev e ./scripts/dev.sh. O guia completo, com as dependências de Fedora e Ubuntu, está em docs/user/install.md.

Primeiro start

Depois da instalação, recarregue as units de usuário e inicie o socket:

systemctl --user daemon-reload
systemctl --user start podstack.socket
systemctl --user status podstack.socket

O estado esperado é active (listening). O podstack.service não é habilitado no boot; ele é ativado na primeira conexão ao socket e permanece ativo até o fim da sessão.

podstack status
podstack doctor

podstack status deve mostrar estado: ok e engine: running; podstack doctor termina com exit 0 quando os checks passam.

Setup em 7 etapas

Na primeira execução, a GUI abre o assistente e mantém a tela principal bloqueada enquanto os checks obrigatórios não passam. As etapas são:

  1. Boas-vindas — explica o que será feito; nada é alterado.
  2. Diagnóstico — checks somente leitura de Docker, Podman, QEMU/KVM, /dev/kvm, virtiofsd, systemd de usuário, SQLite, Caddy e k3s.
  3. Podman — instala/atualiza o Podman e ativa o podman.socket rootless. O Docker não é removido por padrão.
  4. QEMU/KVM — instala QEMU, OVMF, virtiofsd e libvirt opcional. No Ubuntu usa ovmf, qemu-system-x86, qemu-utils e virtiofsd; se a instalação falhar, o erro do helper aparece no painel de log/rodapé. Sem /dev/kvm, avisa e permite TCG.
  5. Componentes — socket/rootless/SQLite são obrigatórios; Caddy é opcional. O k3s não é instalado no host.
  6. Validação — checklist final, separando obrigatórios de opcionais.
  7. Pronto — resumo e abertura do app; grava setup.completed.

Veja Onboarding: as 7 telas para o detalhe de cada etapa e as capturas reais. Os mesmos checks podem ser feitos pela CLI:

podstack setup --check       # somente leitura
podstack setup --validate    # validação final; exit 1 se houver pendência obrigatória
podstack setup               # resumo do estado atual (igual a --status)

Instalações e ativações pela CLI:

podstack setup --apply socket                 # ativa o podman.socket; não exige helper
podstack setup --apply podman                 # instala/atualiza o Podman; exige helper
podstack setup --apply qemu                   # instala QEMU/OVMF/virtiofsd; exige helper
podstack setup --apply components --caddy     # instala o Caddy; exige helper

Ações privilegiadas

--apply inicia um job no daemon e imprime o jobId; o progresso detalhado aparece na GUI e nos eventos do daemon. A GUI nunca executa sudo ou shell. Se o helper falhar (por exemplo, pacote inexistente), a mensagem de erro aparece no painel de log e no rodapé do setup.

Helper e polkit

O podstack-helper é um serviço de sistema, com API declarativa e allowlist. Ele existe para ações que precisam de root, não para executar comandos arbitrários:

Ação Para que serve
install-packages / remove-packages Instalar/remover pacotes allowlistados (Podman, QEMU, virtiofsd, Caddy, remoção opt-in do Docker).
bind-ports Criar unidades systemd para as portas 80/443.
dns-zone Instalar/remover o drop-in do systemd-resolved para *.podstack.local.
trust-ca Confiar/remover a CA local no trust store do sistema.
open-ports / close-ports Abrir/fechar portas no firewall em modo runtime. 
systemctl status podstack-helper.service
journalctl -u podstack-helper.service -n 100 --no-pager

Se o helper não estiver instalado, o setup ainda consegue ativar o podman.socket; as ações que instalam pacotes, configuram DNS/CA ou abrem portas falham com PODSTACK_HELPER_REQUIRED ou PODSTACK_HELPER_UNAVAILABLE.

Polkit precisa de uma sessão gráfica

O polkit pede autenticação na sessão ativa. Em uma sessão sem agente polkit (por exemplo, SSH sem sessão gráfica), a autorização falha; rode o setup a partir do desktop.

Verificar a instalação

Verificação Comando Resultado esperado
Versão podstack version PodStack 0.1.3
Socket de usuário systemctl --user status podstack.socket active (listening)
Daemon e engine podstack status estado: ok e engine: running
Diagnóstico rápido podstack doctor checks [ok]; exit 0
Validação do setup podstack setup --validate Validação OK.; exit 0

podstack doctor verifica o socket do daemon e o socket do Podman. Se algum check falhar, ele mostra a ação sugerida e retorna exit 1; se o daemon não responder, retorna exit 7.

Atualizar e desinstalar

Atualizar

Os updates são assinados e verificados antes de aplicar. Para consultar o manifesto:

podstack update --check

O comando retorna exit 3 quando há uma versão nova e exit 1 quando a checagem está indisponível. A partir da 0.1.4, a GUI oferece Instalar atualização e o CLI aceita podstack update --install (com consentimento, assinatura e reinício); o app fecha e reabre ao final. Em caso de falha, --resume retoma e --clear-state limpa o estado. O caminho manual continua válido: sudo dnf upgrade podstack ou sudo apt upgrade podstack.

Os logs do app e do update ficam em ~/.local/state/podstack/logs/ por 7 dias; use podstack system logs ou a página Logs na GUI, e podstack report --include-logs para um diagnóstico redigido.

Desinstalar

# RPM
sudo systemctl --global disable podstack.socket
sudo dnf remove podstack-helper podstack

# DEB
sudo systemctl --global disable podstack.socket
sudo apt remove podstack

Depois da remoção, recarregue as units de usuário com systemctl --user daemon-reload. A desinstalação remove binários, units, política polkit e arquivos de sistema, mas não remove os dados do usuário:

~/.config/podstack/       # configuração (config.json, 0600)
~/.local/share/podstack/  # machines, kubeconfigs, CA/Caddy
~/.local/state/podstack/  # estado, jobs, reports
~/.cache/podstack/        # cache, incluindo imagens cloud
$XDG_RUNTIME_DIR/podstack/  # socket e estado de runtime (some no logout)

Containers, imagens, volumes e redes continuam no storage do Podman. Se você ativou a CA local ou o DNS de *.podstack.local, remova os artefatos do sistema antes de apagar os dados; o guia completo está em docs/user/install.md.

Limitações de instalação

  • O Flatpak é um cliente: o daemon e o helper precisam estar instalados no host.
  • A validação de instalação limpa (T7-07/T7-14) ainda está em andamento; trate o checklist acima como a verificação mínima da versão 0.1.4.
  • Esta documentação não fixa uma URL de repositório; use o arquivo RPM/DEB gerado localmente ou o repositório que você configurou.
