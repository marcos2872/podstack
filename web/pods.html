Pods

Agrupe containers do Podman em pods e controle o ciclo de vida do grupo inteiro — sem confundir com os Pods do Kubernetes, que vivem no cluster k3s.

PodStack 0.1.0Documentação de usuário

Visão geral

Um pod do Podman é um agrupamento de containers que compartilham recursos de rede e podem ser iniciados, parados e reiniciados juntos. A seção Pods lista NAME, STATUS, CONTAINERS e o ID.

Pods do Podman ficam no grupo Engine da barra lateral. Os Pods do Kubernetes são outra entidade e aparecem na página Kubernetes; não são o mesmo item.

Na interface

  1. Abra Pods na barra lateral.
  2. Clique em Criar, informe o Nome e confirme em Criar.
  3. Selecione o pod e use Start, Stop ou Restart para controlar o grupo.
  4. Para remover, clique em Remover e confirme; o pod e seus containers são removidos.

A lista aceita multi-seleção. O diálogo de remoção avisa que o pod e seus containers serão removidos. Não há, nesta versão, uma tela para adicionar containers a um pod existente ou definir portas do pod pela GUI.

Não confunda com Kubernetes

Pods do Podman são gerenciados pelo engine local e aparecem em Pods. Pods do Kubernetes pertencem ao cluster k3s, usam namespaces e aparecem em Kubernetes. Os comandos podstack pods não operam o cluster Kubernetes.

Na CLI

Comando Flags O que faz
podstack pods ls / list — Lista nome, status, containers e ID.
podstack pods create <nome> — Cria um pod vazio com o nome informado.
podstack pods start <id|nome> — Inicia o pod.
podstack pods stop <id|nome> — Para o pod.
podstack pods restart <id|nome> — Reinicia o pod.
podstack pods rm <id|nome> --force Remove o pod e seus containers. 
podstack pods create web
podstack pods ls
podstack pods start web
podstack pods restart web
podstack pods stop web
podstack pods rm web

Referência rápida

Ação Na GUI Na CLI
Listar Pods podstack pods ls
Criar Criar → nome podstack pods create
Iniciar / parar / reiniciar Start / Stop / Restart podstack pods start|stop|restart
Remover Remover → confirmar podstack pods rm [--force]

Limitações

  • Não há ação para adicionar containers a um pod existente na GUI/CLI 0.1.0.
  • A criação aceita apenas o nome; portas, rede e volumes do pod não são configuráveis nesse fluxo.
  • Não há comando de logs ou inspect específico de pod; use os logs do container ou o Podman diretamente.
  • Pods do Podman e Pods do Kubernetes são modelos diferentes; a página Kubernetes não lista pods do engine.
