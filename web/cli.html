PodStack 0.1.4Documentação de usuário

Visão geral

O pacote instala podstack (CLI), podstackd (daemon) e podstack-gui. O CLI conversa com o daemon pelo socket Unix do usuário; o daemon sobe sob demanda quando podstack.socket está ativo. No build de desenvolvimento, o binário fica em build/dev/podstack.

podstack help
podstack version
podstack status

Convenções: <id|nome> aceita o ID ou o nome do recurso. Não há flags globais como --machine ou --format; cada comando tem as suas. O CLI 0.1.4 não cria, inicia, para nem remove containers: use a GUI para o ciclo de vida. --force/--yes só existem nos comandos listados e não são globais.

Daemon, socket e ativação

O socket de controle fica em $XDG_RUNTIME_DIR/podstack/control.sock, com diretório 0700 e socket 0600. Não há TCP; o daemon roda com o seu usuário. O podstack.service não é habilitado no boot: ele é ativado na primeira conexão ao socket e permanece ativo até o fim da sessão.

systemctl --user daemon-reload
systemctl --user start podstack.socket
systemctl --user status podstack.socket
podstack status
podstack doctor

Para isolar um daemon de desenvolvimento, use PODSTACK_CONTROL_SOCKET:

PODSTACK_CONTROL_SOCKET=/tmp/podstack-dev.sock ./build/dev/podstack status
PODSTACK_CONTROL_SOCKET=/tmp/podstack-dev.sock ./build/dev/podstackd --socket /tmp/podstack-dev.sock

Grupos de comandos

Diagnóstico e monitoramento

Comando O que faz
podstack version Mostra PodStack 0.1.4.
podstack status Estado do daemon e do Podman. Exit 7 quando o daemon não responde; exit 1 quando o status contém erro.
podstack doctor Diagnóstico rápido do socket do daemon e do socket do Podman. Exit 1 se algum check falhar.
podstack report [--include-logs] [--json] Gera um relatório redigido em ~/.local/state/podstack/reports/ (0600) com caminho e SHA-256.
podstack top [--once] [--interval S] [--json] [--plain] Monitora CPU/memória/containers; --once espera duas amostras.
podstack update --check [--json] [--channel stable|beta] Consulta o manifesto assinado; não instala nada. Exit 3 se houver versão nova.
podstack update --install [--yes] [--json] [--resume|--clear-state] Baixa/valida o pacote e instala pelo helper, com consentimento e reinício. Exit 0/1/2/6/8/9 (nunca 3).

Containers

Comando Flags O que faz
podstack ps --all/-a, --running/-r, --stopped/-s, --format table|json, --quiet/-q Lista containers; sem filtro, apenas em execução.
podstack inspect <id|nome> — JSON bruto do container.
podstack exec <id|nome> -- <cmd...> — Execução one-shot; devolve o exit code do comando.
podstack pause|unpause <id|nome> — Pausa/despausa.
podstack kill <id|nome> --signal S Envia um sinal.
podstack checkpoint <id|nome> --leave-running, --tcp-established, --json Checkpoint CRIU.
podstack restore <id|nome> --tcp-established, --json Restaura o checkpoint CRIU.

Não existem, nesta versão, comandos de CLI para criar, iniciar, parar, reiniciar, renomear, duplicar ou remover containers. Use a GUI ou o Podman diretamente.

Imagens, volumes, redes e pods

Grupo Comandos Observações
Imagens images [ls|pull|push|rm|prune|history|tag|untag|inspect|export|load] Pull aceita --platform; push exige --destination; não aceita --json, exceto o JSON bruto de inspect.
Volumes volumes [ls|create|rm|prune|clone|export|import|import-host] export/import usam .tar.zst; import-host copia um diretório do host.
Redes networks [ls|create|rm|connect|disconnect] Create aceita --subnet, --gateway, --driver, --ipv6; connect aceita --alias repetível.
Pods pods [ls|create|start|stop|restart|rm] Create aceita apenas o nome; rm aceita --force.

Compose e builds

Comando Flags O que faz
podstack compose ls — Projetos agrupados por labels.
podstack compose up <diretório> [serviço] — Sobe o projeto; sempre destacado, sem -d.
podstack compose down <diretório> [serviço] --volumes Derruba; sem --volumes, preserva os volumes.
podstack compose restart|stop|start <diretório> [serviço] — Controla o projeto ou um serviço.
podstack compose logs <projeto> [serviço] — Stream agregado ou por serviço.
podstack build <contexto> -t <tag> -f Dockerfile, --build-arg K=V, --platform p1,p2 Build via Libpod (1 plataforma) ou manifest list (2+).
podstack builds ls / rm <id> — Histórico SQLite; remover o registro não remove a imagem.

Machines

O grupo machine cobre ciclo de vida, SSH, arquivos, portas, snapshots, serial, USB, áudio, clone, rename, default, distros, update e export/import. A referência completa, com exemplos e flags, está em Machines → Na CLI.

podstack machine distros
podstack machine create ubuntu:24.04 dev --cpus 2 --memory 4G --disk 20G
podstack machine list
podstack machine info dev
podstack ssh dev
podstack machine snapshot create dev antes-upgrade
podstack machine export dev ~/dev-backup.tar.zst

Kubernetes, sistema, configuração e setup

Comando Flags O que faz
podstack kube info --cluster NOME, --json Estado, contexto, API e kubeconfig.
podstack kube env --cluster NOME Imprime export KUBECONFIG=....
podstack kube start — Cria a VM e instala o k3s.
podstack kube stop|disable --force Remove a VM, o disco e o kubeconfig.
podstack kube context [use <nome>] — Mostra ou troca o contexto.
podstack system df --detailed, --json Uso de disco e prévia de prune.
podstack system disk --json Espaço livre e aviso de disco baixo.
podstack system emulation --json Arquitetura do host e handlers binfmt/FEX.
podstack system logs --follow, --since 7d|ISO, --level, --component, --json, --export, --clear Logs do app dos últimos 7 dias; filtra, exporta (0600) e limpa. helper/package usam polkit.
podstack config show|get|set|add|remove|reset|schema --json, --all, --yes Lê e altera as 86 chaves de configuração.
podstack setup --check, --status, --validate, --apply podman|qemu|components|socket, --docker-impact [--json], --remove-docker --yes Setup/onboarding e ações privilegiadas via helper.

JSON, exit codes e automação

Comandos com saída JSON:

  • ps --format json (ou --format=json)
  • checkpoint --json, restore --json
  • machine ... --json (list, info, logs, console com --no-follow, start/stop/restart/delete, rename, clone, update, default, distros, port, snapshot, serial, usb, audio, export, import)
  • kube info --json
  • system df|disk|emulation --json, system logs --json
  • config show|get|schema --json
  • top --json, update --check|--install --json, report --json, setup --docker-impact --json

images, volumes, networks, pods, compose e builds não aceitam --json nesta versão; images inspect sempre imprime o JSON bruto.

Código Significado
0 Sucesso.
1 Erro genérico; também usado por doctor/setup --validate com pendência, por update --check quando a checagem está indisponível e por update --install quando a instalação falha.
2 Uso inválido, flag desconhecida ou confirmação ausente em modo não interativo.
3 update --check encontrou versão nova. update --install nunca retorna 3.
6 Consentimento/polkit negado no update assistido.
7 Daemon ou engine indisponível (PODSTACK_DAEMON_UNAVAILABLE/PODSTACK_ENGINE_UNAVAILABLE).
8 Timeout no download, stage ou instalação do update.
9 Update cancelado antes de a unidade transiente começar.

podstack exec devolve o exit code do comando executado no container (0–255) quando o comando chega a rodar; erros do próprio CLI seguem a tabela acima. Os erros do daemon vêm no formato {code, message, detail, remediation}; o CLI imprime a mensagem, o detalhe e a ação sugerida.

Variáveis de ambiente

Variável Efeito
PODSTACK_CONTROL_SOCKET Usa outro socket de controle (desenvolvimento/teste).
PODSTACK_PODMAN_SOCKET Usa outro socket do Podman.
PODSTACK_PODMAN_CLI Usa outro binário do Podman para operações que chamam o CLI.
PODSTACK_COMPOSE_PROVIDER Força o binário do provider Compose.
PODSTACK_SSH_CONFIG Usa outro arquivo de configuração SSH.
PODSTACK_SSH_BINARY / PODSTACK_SCP_BINARY Usa outros binários de SSH/SCP.
PODSTACK_VIRTIOFSD_BINARY Usa outro binário do virtiofsd.

Essas variáveis são principalmente para diagnóstico e desenvolvimento; no uso normal, deixe os defaults.

Exemplos de automação

# listar containers parados em JSON e extrair nomes
podstack ps --all --format json | jq -r '.items[] | select(.state != "running") | .name'

# estado e diagnóstico em CI
podstack status
podstack doctor

# build e histórico
podstack build ./app -t local/app:ci --build-arg VERSION=0.1.4
podstack builds

# machine descartável
podstack machine create ubuntu:24.04 ci --cpus 2 --memory 4G --disk 20G
podstack ssh ci -- uname -a
podstack machine delete ci

# cluster e kubeconfig isolado
podstack kube start
eval "$(podstack kube env)"
kubectl get nodes

Limitações

  • Não há podstack run, create, start, stop ou remove de containers.
  • Não há flags globais; cada comando tem suas próprias flags.
  • images, volumes, networks, pods, compose e builds não têm --json.
  • compose up é sempre destacado e recebe o diretório, não -f.
  • O CLI não instala o kubectl nem o provider Compose.
  • Comandos destrutivos como machine delete e kube stop não pedem confirmação interativa.
