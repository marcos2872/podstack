Machines

Crie VMs Linux com cloud-init e QEMU/KVM, acesse por SSH, compartilhe diretórios com virtiofs e controle portas, snapshots e hardware no mesmo lugar.

PodStack 0.1.2Documentação de usuário

Visão geral

As Machines são VMs Linux completas, não containers. O PodStack usa QEMU/KVM, uma imagem cloud da distro, um disco qcow2 esparso e um seed cloud-init para criar o usuário, a chave SSH e a rede. Sem /dev/kvm, a VM usa TCG e fica bem mais lenta.

Cada machine tem uma chave ed25519 própria e um bloco gerenciado em ~/.ssh/config quando ssh.manageConfig está ativo. O usuário padrão é podstack; a porta SSH é publicada em 127.0.0.1 e gerenciada automaticamente.

Distros disponíveis em 0.1.2: ubuntu:24.04, debian:12 e fedora:44 (amd64). Os defaults são 2 CPUs, 4 GiB de memória, 20 GiB de disco e usuário podstack.

Na interface

Criar uma machine

  1. Abra Machines na barra lateral.
  2. Clique em Nova machine.
  3. Escolha Distro, informe Nome, CPUs, Memória (GiB), Disco (GiB) e Usuário.
  4. Opcionalmente, informe Senha do usuário (gravada apenas como hash), um user-data (cloud-config) e mounts do host.
  5. Marque Modo isolado, Isolar a rede da machine ou Encaminhar o SSH agent conforme o caso.
  6. Clique em Criar e acompanhe o progresso: download da imagem cloud, disco qcow2, seed, QEMU e espera do SSH.

O campo de mounts aceita uma linha por mount no formato origem:destino[:ro], por exemplo /home/voce/projetos:/mnt/podstack/projetos. O limite é de 8 mounts; a origem precisa existir e ser um diretório absoluto. Modo isolado desabilita mounts e agent SSH, força a rede restrita e limpa esses campos; a porta SSH local continua disponível.

Agent forwarding é sensível

Com Encaminhar o SSH agent ativo, processos dentro do guest podem usar as chaves carregadas no seu agent do host. Ative apenas em machines confiáveis. O toggle fica no Info e pode ser alterado sem reiniciar a machine.

Ciclo de vida e ações

Selecione uma machine para ver o card lateral. No cabeçalho e no card estão:

  • Iniciar, Parar e Restart.
  • SSH abre o detalhe já na aba Terminal.
  • Expandir abre o detalhe completo em overlay, com Esc para fechar.
  • Renomear, Clonar, Recursos, Portas, Serial, USB, Snapshots e Exportar.
  • Excluir pede confirmação e remove a machine e o disco.

Recursos altera CPUs, memória e disco. CPUs e memória passam a valer no próximo boot; o disco só cresce e a partição/filesystem do guest não é expandida automaticamente. Clonar cria uma cópia independente; Exportar grava um .tar.zst com disco, seed e chaves.

Detalhe: Info, Logs, Stats, Terminal e Files

O detalhe da machine tem cinco abas:

Aba O que mostra Observações
Info Distro, arch, CPUs, memória, disco, criada, último boot, mounts virtiofs, portas e o checkbox Encaminhar SSH agent. Os mounts aparecem como origem → destino, com marca de somente leitura.
Logs Últimas 200 linhas de console.log. Copiar, Atualizar e Seguir console; o follow para ao trocar de aba/machine.
Stats CPU, RAM usada/total, disco usado/total, rede ↓/↑ e I/O de disco. Coleta por SSH a cada 2 s; machine parada mostra estado vazio.
Terminal Sessão SSH com a chave da machine, IdentitiesOnly=yes e StrictHostKeyChecking=accept-new. Nova sessão em janela abre um terminal externo; usa -A quando o agent está encaminhado.
Files Navegação remota, download clicando no arquivo (destino ~/Downloads) e upload pelo campo + Enviar. Erros ficam no próprio painel, sem poluir o erro global.

O console serial é somente texto. Não há VNC nem console gráfico; se o SSH falhar, use Logs ou podstack machine console para ver o boot.

Portas, serial, USB, áudio e snapshots

  • Portas abre o diálogo de port forwarding: lista as portas extras com host → guest, protocolo, bind e rótulo; permite adicionar e remover. A porta SSH é gerenciada e não aparece na lista. Alterar portas reinicia a machine se ela estiver rodando.
  • Serial lista portas do host (ttyUSB/ttyACM/ttyS) e as anexadas; anexar/desanexar reinicia a machine.
  • USB lista dispositivos do host por bus:address e os anexados; anexar/desanexar reinicia a machine.
  • Ativar/Desativar áudio usa PipeWire e reinicia a machine se estiver rodando.
  • Snapshots cria, lista, restaura e remove snapshots internos do qcow2. Restaurar substitui o disco atual; a GUI pede confirmação.

Snapshots são do disco, não da memória

Os snapshots são internos do qcow2 e não têm snapshot de memória/VM state. Criar, restaurar ou remover para a machine quando necessário e a reinicia ao final. export, import e clone não preservam os snapshots internos.

Na CLI

O CLI cobre o ciclo de vida, SSH, arquivos, portas, snapshots, serial, USB, áudio, clone, rename, default e export/import. A criação por CLI não tem flags de mount; mounts são configurados na GUI/RPC. A senha do usuário também é um campo da GUI, não uma flag do CLI.

Ciclo de vida e informação

Comando Flags O que faz
podstack machine distros --json Lista imagens cloud disponíveis e o cache local.
podstack machine create DISTRO[:VER] NOME --cpus N, --memory 4G, --disk 20G, --user U, --user-data ARQUIVO, --isolate-network, --forward-ssh-agent, --isolated Cria a machine e provisiona via cloud-init.
podstack machine list --json Lista nome, distro, arch, estado e SSH.
podstack machine info <id|nome> --json Mostra os dados da machine.
podstack machine start|stop|restart <id|nome> --force (stop), --json Controla o ciclo de vida.
podstack machine delete <id|nome> --force, --json Remove a machine e o disco, sem confirmação interativa no CLI.
podstack machine rename <id|nome> <novo> --json Renomeia e atualiza o bloco SSH.
podstack machine clone <id|nome> <novo> --json Cria uma cópia independente.
podstack machine update <id|nome> --cpus N, --memory 4G, --disk 40G, --forward-agent, --no-forward-agent, --json Atualiza recursos ou o agent; disco só cresce.
podstack machine default [<id|nome>] --json Mostra ou define a machine default do CLI.
podstack machine logs <id|nome> --tail N, --json Mostra as últimas linhas do console.
podstack machine console <id|nome> --tail BYTES, --no-follow, --json (só com --no-follow) Lê o console serial; sem --no-follow, segue até Ctrl+C. 
podstack machine distros

podstack machine list --json
podstack machine info dev
podstack machine start dev
podstack machine stop dev
podstack machine update dev --cpus 4 --memory 8G
podstack machine console dev --no-follow --tail 65536
podstack machine logs dev --tail 200

SSH, arquivos e portas

Comando Flags O que faz
podstack ssh [<id|nome>] --x11, --x11-trusted, -- <cmd...> Abre SSH; sem id usa a machine default. --x11 adiciona -X e --x11-trusted adiciona -Y.
podstack machine ssh [<id|nome>] Idem Alias explícito para o SSH da machine.
podstack machine files ls <id|nome> --path P, --json Lista arquivos remotos via SSH.
podstack machine pull <id|nome> <remoto> <local> — Copia guest → host via SCP.
podstack machine push <id|nome> <local> <remoto> — Copia host → guest via SCP.
podstack machine port ls <id|nome> --json Lista portas encaminhadas; a SSH é gerenciada.
podstack machine port add <id|nome> --host N, --guest N, --udp, --lan, --label L, --json Adiciona uma porta; reinicia se a machine estiver rodando.
podstack machine port rm <id|nome> <portId|hostPort> --json Remove uma porta; recusa a SSH e hostPort ambíguo. 
podstack ssh dev
podstack ssh dev -- uname -a
podstack machine ssh dev --x11 -- xeyes
podstack machine files ls dev --path /var/log
podstack machine pull dev /var/log/app.log ./app.log
podstack machine push dev ./app.tar /home/podstack/
podstack machine port add dev --host 8080 --guest 80 --label web
podstack machine port ls dev
podstack machine port rm dev 8080

O bind padrão das portas é 127.0.0.1. --lan publica em 0.0.0.0 e exige liberação do firewall; use apenas quando necessário. A porta SSH é publicada automaticamente e não pode ser removida.

Export/import, snapshots e hardware

Comando Flags O que faz
podstack machine export <id|nome> <arquivo> --force, --json Pausa a machine e grava um .tar.zst com disco, seed e chaves; use caminho absoluto.
podstack machine import <arquivo> --name N, --force, --json Valida manifesto/checksums e cria uma machine nova.
podstack machine snapshot ls <id|nome> --json Lista snapshots internos do qcow2.
podstack machine snapshot create <id|nome> <nome> --json Cria um snapshot; para/reinicia se rodando.
podstack machine snapshot restore <id|nome> <nome> --json Substitui o disco pelo snapshot; não existe --force.
podstack machine snapshot rm <id|nome> <nome> --json Remove o snapshot; operação destrutiva.
podstack machine serial list|attach|detach <id|nome> ... --json Gerencia portas seriais do host; anexar reinicia.
podstack machine usb list|attach|detach <id|nome> ... --json Gerencia dispositivos USB por BUS:ADDR; anexar reinicia.
podstack machine audio <id|nome> on|off --json Liga/desliga áudio PipeWire; reinicia se rodando. 
podstack machine snapshot create dev antes-upgrade
podstack machine snapshot ls dev
podstack machine snapshot restore dev antes-upgrade
podstack machine export dev ~/dev-backup.tar.zst
podstack machine import ~/dev-backup.tar.zst --name dev-restaurada
podstack machine usb list dev
podstack machine audio dev on

Restaurar snapshot substitui o disco

Restaurar um snapshot descarta alterações posteriores do disco. Remover um snapshot é destrutivo. A machine é parada e reiniciada automaticamente quando necessário. Não existe --force para snapshot restore.

Limitações

  • Sem VNC: o console serial é somente texto; não há console gráfico.
  • Export/import e clone não preservam snapshots internos do qcow2.
  • Mounts e senha só na GUI/RPC: machine create não aceita flags de mount nem senha.
  • Disco só cresce: não há shrink; crescer o disco não expande a partição/filesystem do guest.
  • X11 depende do host e do guest: precisa de DISPLAY/XAUTHORITY e xauth no guest; Wayland nativo não é encaminhado.
  • Áudio depende do guest: o host usa PipeWire; o guest precisa de stack de áudio compatível.
  • USB/serial/áudio reiniciam a machine quando ela está rodando.
  • Delete no CLI não pede confirmação e remove a machine e o disco.
  • Modo isolado não é fronteira de segurança contra malware; o kernel do guest é separado, mas QEMU é o limite.
